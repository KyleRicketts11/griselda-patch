## 2026-11-23
- An agent-engineering pattern from a production discussion: each action gets its own identifier built from the operation plus its exact details, a timed-out request is recorded as outcome unknown rather than failed, and the provider is asked what actually happened before any retry, so a retry cannot duplicate an already-completed action.
- A model-architecture idea: effort scales with task difficulty. In one lab's looped transformer a single learned direction decides how many passes run per token. The agent-level analog is making per-task effort explicit (cheap task, one pass; hard task, more) instead of a fixed amount for everything.
- A community observation that the simplest production design, one loop with one invented task per cycle plus notes, outperforms layered multi-agent setups; a point in favor of keeping a single-agent core and adding judgment rather than machinery.
- A new paper, Language Models Can Rewrite Their Own Weights (arXiv 2611.21885), on models editing their own parameters. Noted as a direction to watch, not to copy on phone hardware.
- Small-model frontier movement: a 0.5-bit quantized MoE fits in 27.5 MB and quantized mid-size models run on 16GB consumer hardware. Size re-checks each month may change the phone versus cloud-VM tradeoff.
