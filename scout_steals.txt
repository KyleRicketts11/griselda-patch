## 2026-11-28

- TIMEOUT IS NOT A FAILURE VERDICT (from r/AI_Agents): a real-world booking went through while the agent only saw a timeout, so it retried and double-booked. When an action's outcome is UNKNOWN, confirm the result out-of-band (re-read the file, re-check the record) before retrying. Not seeing success is not proof of failure, for griselda's own queued actions too.
- TEST AGAINST DATA THAT IS WRONG ON PURPOSE (r/AI_Agents, 52-up thread): agents fail where inputs are deliberately corrupted, contradictory, or poisoned, not on happy paths. A couple of tasks in the frozen eval set where the INPUT is wrong, checking whether she detects, flags, or silently trusts it, would extend the set cheaply.
- READ A SERVICE'S TERMS BEFORE ACTING FOR SOMEONE (United Airlines, Nov 11 contract change): the airline now names agent-made bookings a prohibited ticketing practice and can cancel them without notice. Real-world services are starting to refuse agent actions in their terms. Before acting on someone's behalf at a service, read what its rules say about agents.
- DOWNLOADED MODEL FILES ARE UNTRUSTED INPUT (Malspark GGUF malware scan): malware hid after the last tensor of GGUF files and was armed later through the chat template, 2,428 downloads of five poisoned models. Anything griselda pulls from models.txt comes from the internet; treat downloaded weights as untrusted and verify what you run.
- PIN WHAT A SINGLE MAINTAINER BUILDS (Heretic archived, Nov 28): the top open-source model abliteration tool went read-only overnight with no successor. Tools built by one person can stop at any moment; note which versions you depend on and which are unmaintained.

## 2026-11-27

- STALE RULES SLOW NEW MODELS (Philipp Schmid at Google DeepMind on Gemini 4 Neon): guardrails and rules written for older models were slowing the new one down and making it fail edge cases it could solve on its own. When your model or setup changes, old rules.txt lines are not automatically still helpful; a rule written for an older griselda can now hurt more than help. Worth a periodic read of rules.txt against what you actually do now.
- FIX TOOL ERRORS IN THE TOOL, NOT THE PROMPT (r/AI_Agents): an agent looping forever on tool errors was mostly fixed by changing what the TOOL returns (actionable error messages) rather than prompt wording. If a read_url or other tool call fails, your retry should change because the error told you what to do differently; identical retries are the loop.
- FRESH EVIDENCE BEATS AN OLD FILE (r/AI_Agents study): one agent followed an outdated rulebook file over the code it had just read in about 90% of cases. When a stored file and something you just observed disagree, check the file's date and weight fresh evidence higher.
- VALIDATION PASSING IS NOT INTEGRITY (8,850 ERP/CRM agent runs): 100% of database-integrity failures had already passed the agent's validation checks. For the claim ledger: a claim being well-formed is not a claim being true. Cross-check new claims against existing ones before saving them as fact.
- RECORD PARTIAL WORK (r/AI_Agents): when a run gets interrupted halfway, the task should be resumable from where it stopped, not restarted. brain_notes.txt entries on what was already done make a crashed task recoverable.

## 2026-11-26

- FINGERPRINT WHAT AN ENDPOINT SERVES (from Modaic's latency profiling of TypeSafe's mystery model Jev across 9,984 prompts): don't trust a model's label; measure it. Latency distributions plus tokenizer behavior across many prompts identified the real backbone. If models.txt ever rotates endpoints, check the key actually serves the model it claims before trusting its answers.
- LOGIN WALLS STOP AGENTS (from a16z's 11,307-run agent shopping study): every test run on a store that required a sign-in stopped before the sale. Account walls are where agents fail, not browsing. When griselda hits a sign-in she can't pass, stop and tell Kyle (matches the browser.md rule).
- PRICE AND REVIEWS BEAT BRAND (same study): price drove 43% of agent picks, brand names showed up in under 1%. Whatever griselda writes for people (a lead follow-up, a comparison), concrete numbers and receipts beat name-dropping.
- AGENT TRACES AS DATA (LangChain shipped Agent Lake, a data lake for agent traces): execution logs stored as first-class, queryable data so past runs can be analyzed later. Same direction as griselda's append-only brain_notes.txt: structured records pay off when you want to audit what happened.
- WATCH (context, nothing to act on): Reuters reports US chip curbs and anti-distillation enforcement are stalling Chinese flagship releases; Z.AI missed its November plan for GLM-5.5 and Moonshot expects release cycles could double without overseas compute. If Chinese open-weights slow down, the models griselda can pull from shift.

## 2026-11-25

- RULES OUTSIDE THE PROMPT (from r/AI_Agents, a production support-agent builder): a line in the system prompt is a request, not a limit. Enforce important rules in structural checks outside the prompt (code-level guardrails on tool calls), because prompt instructions get ignored under pressure. This is the same lesson as the act-rule hardening in rules.txt; the next level up is a check in code, not words.
- ALREADY-DONE DETECTION (from r/AI_Agents): the question worth testing is whether an agent can tell a task is ALREADY finished, so it stops re-doing work. Keep a record of what was completed and check it before starting anything that looks similar. Extends yesterday's verification-before-done steal.
- COMPRESSION PATTERN (from a walkthrough of how 1M tokens of context shrank from 130TB to 890MB): recompute what you can recompute, compress what you must keep, and never store a score you throw away. Applies to any growing memory file: keep decisions and outcomes, drop verbatim detail you could re-derive.
- BENCHMARKS ARE NOT LONG TASKS (from r/LocalLLaMA real-world testing of Inkling 2 Mini): a model can win benchmarks and still fall apart on long tasks. Judge a model or a prompt change on your own long-running workflow, not its scorecard.

## 2026-11-24

- VERIFICATION BEFORE DONE (from r/AI_Agents, a 17-day self-repairing game agent): the hard part is not fixing bugs, it is KNOWING a fix worked. When you finish a self-picked task, the check is part of the task: re-read the file you changed or run the command, and log in brain_notes.txt what you verified (not just what you did).
- MODEL SWAP RULE (from r/AI_Agents): before trusting an agent moved to a new model, delete the file it is supposed to edit and watch what happens. Old-model passes do not transfer. If your model ever rotates in models.txt, rerun a couple of known tasks after the swap before trusting your new behavior.
- CLAIM LABELS (from Anthropic releasing a Claude-authored VP != VNP proof with a Lean formalization, README says no human mathematician has checked it): when you report a result, say which part was machine-checked, which was human-checked, and which was neither. A claim with a receipt is not a result.
